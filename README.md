# БИОТ – Допуск к работе

Веб-тренажёр по технике безопасности для монтёров Казахтелекома. Пять заданий-сцен у сельской АТС: на каждой нужно найти нарушения и расставить их от наиболее критичного к менее значимому. Бэкенда нет, результаты хранятся в браузере (localStorage).

Стек: Vite, React, TypeScript, Tailwind CSS, Zustand, @dnd-kit, jsPDF.

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # сборка в dist/
npm run preview    # проверить собранную версию
```

## Как устроено

| Где | Что |
| --- | --- |
| `public/tasks.json` | задания: тексты, ранги, координаты областей, пояснения |
| `public/scenes/` | картинки сцен `t1.webp` … `t5.webp` |
| `public/logo.svg` | логотип в шапке и в PDF |
| `src/config.ts` | порог допуска, лимиты времени, веса баллов, список подразделений |
| `src/lib/scoring.ts` | подсчёт баллов |
| `src/screens/` | экраны: старт, задание, итог, редактор |
| `docs/scene-prompts.md` | промты для генерации картинок |

### Баллы (`src/config.ts → score`)

- `found`: начисляется за каждое найденное нарушение;
- `distractorPenalty`: вычитается за каждый выбранный отвлекающий вариант;
- `perfectOrderBonus`: начисляется, если найдены все нарушения и порядок полностью верный;
- `partialOrderBonusMax`: потолок частичного бонуса за неидеальный порядок. Формула: `max × доля пар в верном порядке × доля найденных`.

Баллы за задание не уходят ниже нуля. Итоговый процент = сумма баллов / сумма максимумов. Порог допуска задаёт `passThresholdPercent` (по умолчанию 80).

## Как заменить картинки

1. Сгенерируйте сцены по промтам из [docs/scene-prompts.md](docs/scene-prompts.md). Формат 16:9, лучше 1920×1080.
2. Сохраните их как `public/scenes/t1.webp` … `t5.webp`. Подойдут и `.jpg` или `.png`, тогда поправьте поле `image` в `tasks.json`.
3. Пока картинки нет, тренажёр показывает схематичную заглушку с подписанными областями из `tasks.json`. Так игру можно проверить без готовых картинок.

Миниатюры на карточках вырезаются из той же картинки по координатам области, отдельные файлы для них не нужны.

## Как заменить задания

Файл `public/tasks.json` содержит массив заданий:

```json
{
  "id": "t1",
  "title": "Опора у сельской АТС",
  "image": "/scenes/t1.webp",
  "layout": "list",
  "timeLimitSec": 60,
  "items": [
    {
      "id": "no-helmet",
      "text": "Отсутствует каска",
      "isViolation": true,
      "rank": 1,
      "area": { "x": 30, "y": 40, "w": 12, "h": 15 },
      "explanation": "Пояснение для разбора",
      "rule": "Правила ТБ, п. 12"
    }
  ]
}
```

- `layout`: `"list"` (вертикальный список, порядок можно менять перетаскиванием) или `"grid"` (сетка 3×2, нужно ровно 6 карточек);
- `timeLimitSec`: лимит времени на задание. Если поле не указано, берётся `defaultTimeLimitSec` из конфига;
- `isViolation: false` отмечает отвлекающий вариант, то есть то, что на сцене сделано правильно. У таких карточек нет `rank`;
- `rank`: позиция по критичности, 1 — самое опасное. Ранги нарушений внутри задания должны идти от 1 до N без пропусков;
- `area`: прямоугольник в процентах от ширины и высоты картинки;
- `rule`: необязательная ссылка на пункт правил, показывается в разборе под пояснением.

В примерах пункты правил стоят как «п. __ (заменить)», вместо них подставьте реальные пункты.

## Редактор разметки `/editor`

Скрытая страница для разметки сцен: http://localhost:5173/editor (на хостинге без SPA-маршрутов откройте `/#editor`).

1. Выберите задание из `tasks.json` или создайте новое. Нажмите «Загрузить картинку». Путь в поле `image` подставится как `/scenes/<имя файла>`.
2. Обведите мышкой область нарушения, и появится карточка. Область можно перетаскивать за середину, размер меняется за углы, клавиша Delete удаляет выбранную область.
3. Заполните текст, отметьте, нарушение это или отвлекающий вариант, укажите ранг, пояснение и пункт правил. Точные координаты можно поправить числами.
4. Кнопка «Ранги по порядку» нумерует нарушения 1..N в порядке списка; порядок меняется стрелками ▲▼.
5. «Скопировать JSON» копирует одно задание. «Скопировать весь tasks.json» копирует весь файл, где это задание заменено или добавлено: его можно целиком вставить в `public/tasks.json`.
6. Положите сам файл картинки в `public/scenes/`: редактор держит её только в памяти браузера.

Красные рамки — нарушения, зелёные — отвлекающие варианты. Внизу показываются подсказки, например о повторяющихся рангах или карточках без текста. Черновик сохраняется в браузере автоматически.

## 3D-режим ходьбы `/walk` (прототип)

**Сцена 1. Улица у КТПН** — http://localhost:5173/walk: игрок идёт по сельской улице от точки A мимо открытой КТПН к фургону (точка B), подходит к объектам и отмечает нарушения. Порядок отметок меняется перетаскиванием, а в конце показывается тот же разбор, что в основном тренажёре. Карточки берутся из задания `landscape` в `public/walk-tasks.json`: задания режима ходьбы лежат отдельно, чтобы не попасть в основной тренажёр. Объект сцены `item_<id>` соответствует карточке с тем же `id`, к одному объекту можно привязать несколько карточек: `item_<id1>+<id2>`. Свойство `inspect_range` задаёт объекту свой радиус осмотра.

Прежняя сцена «Опора у сельской АТС» открывается по http://localhost:5173/walk?scene=t1, её карточки — задание `t1` в `tasks.json`.

Управление:
- на компьютере: WASD или стрелки — ходьба, Shift — бег, мышь — поворот камеры, колесо — зум, E — отметить следующую неотмеченную карточку рядом, 1–9 — отметить или снять карточку по её номеру в списке;
- на телефоне: экранный джойстик и поворот камеры свайпом.

### Сцена из Blender

- `blender/build_t1.py` собирает сцену скриптом и сохраняет `public/models/t1.glb` и `blender/t1_pole.blend`.
- `blender/build_worker.py` собирает персонажа игрока `public/models/worker.glb` из готовой модели `blender/assets/kazakhtelecom_worker_rounded_realistic.glb`.
- Пересобрать модели: `npm run models`. Нужен Blender 4.5 LTS в PATH.
- `t1_pole.blend` можно открыть в Blender и дорабатывать руками. После правок экспортируйте сцену: File → Export → glTF 2.0 (.glb), включите Include → Custom Properties и сохраните как `public/models/t1.glb`.

Игра понимает роли объектов по их именам:

| Имя объекта в Blender | Роль |
| --- | --- |
| `item_<id>` | объект для осмотра; `<id>` совпадает с id карточки в `tasks.json` (нарушение это или нет, берётся из `tasks.json`) |
| `wall_*` | препятствие |
| любое имя + Custom Property `solid = 1` | тоже препятствие |
| `spawn_A`, `goal_B` | пустышки (Empty): точки старта и финиша |

У модели игрока части `leg_L`, `leg_R`, `arm_L`, `arm_R` должны иметь точку опоры (Origin) в бедре и плече: так их можно качать при ходьбе.

## Локация 2 «Город» `/city`

Тот же режим ходьбы от третьего лица, что и в локации 1, только в городе. Монтёр идёт от точки A вдоль оживлённой улицы к открытому колодцу кабельной канализации (B): один сотрудник спускается в колодец, второй стоит у края с газоанализатором. Игрок подходит к ним и отмечает нарушения, в конце — тот же разбор. Здания через дорогу (жилые дома, поликлиника, пожарная часть, бизнес-центр, стройка с башенным краном, завод) — фон: по улице едут машины и автобусы, ходят прохожие, поблёскивают окна, кран поворачивает стрелу, из заводской трубы идёт дым.

- **Открытие.** Город закрыт, пока локация 1 (`/walk`) не пройдена с результатом не ниже `passThresholdPercent` (80%). После такого прохождения в разборе локации 1 появляется кнопка «Перейти в «Город»». В режиме разработки (`npm run dev`) город можно открыть без этого: http://localhost:5173/city?open.
- **Карточки** — задание `city` в `public/walk-tasks.json` (текст «Ситуации 2» — поле `briefing`). Нарушения: монтёр без каски, спецобуви и перчаток; спуск без лестницы; бензиновый генератор у люка с подветренной стороны (выхлоп анимирован и уходит в колодец). Правильно: ограждение со знаком, противогаз, инструмент в сумке. Объекты стоят по разные стороны ограждения и осматриваются с малого расстояния (`inspect_range` 0,9–1,5 м), поэтому карточки открываются по очереди, пока игрок обходит место работ.
- **Взгляд от первого лица (Q).** Рядом с монтёром у колодца появляется подсказка «Газоанализатор у монтёра — посмотреть». По Q (или по подсказке) открывается окно: вид его глазами, в руках газоанализатор с мигающим красным «ГАЗ», за ним — колодец. Q или Esc закрывает. В сцене это свойство `look` у объекта и пустышки `pov_<id>` (глаза) и `pov_<id>_target` (куда смотрит); что в руках, задаёт `src/city/gasAnalyzer.ts`.
- **Сцена** — `blender/build_city.py` → `public/models/city.glb` и `blender/city_base.blend`. Общие инструменты (материалы, построитель мешей, окна, деревья в стиле сцены 1, установка готовых моделей) — `blender/lowpoly.py`. Где можно ходить, задают пустышки `walk_min` / `walk_max`.
- **Движок** — тот же `src/walk/engine.ts` с настройками сцены (`WalkOptions`: дальний туман, солнце следует за игроком, «живая улица» из `src/city/ambient.ts`).

## Публикация на Vercel

1. Загрузите репозиторий на GitHub.
2. На [vercel.com](https://vercel.com) нажмите Add New → Project и выберите репозиторий. Vercel сам определит Vite: Build Command `npm run build`, Output Directory `dist`.
3. Нажмите Deploy. Файл `vercel.json` уже настраивает маршруты, поэтому `/editor` открывается напрямую.

Чтобы обновить задания или картинки, закоммитьте изменения в `public/`, и Vercel пересоберёт сайт сам.

Через CLI: `npm i -g vercel && vercel --prod`.

## Данные в браузере

- `biot.player.v1`: последние введённые ФИО, табельный номер и подразделение (подставляются на старте);
- `biot.history.v1`: последние 50 прохождений;
- `biot.editor.draft.v1`: черновик редактора;
- `biot.progress.v1`: лучший результат локации 1 (открывает «Город»).

Если localStorage недоступен (например, в приватном режиме), тренажёр работает, просто ничего не запоминает.
